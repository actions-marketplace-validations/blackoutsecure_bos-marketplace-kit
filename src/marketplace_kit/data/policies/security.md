# Security Policy

## Supported Versions

The latest release of `{{project_name}}` receives security updates.
Older minor versions may receive critical-severity patches at our
discretion; see the [release notes](https://github.com/{{owner}}/{{repo_name}}/releases)
for the current support matrix.

## Reporting a Vulnerability

Please report security vulnerabilities **privately**:

1. **Preferred:** [GitHub private vulnerability reporting](https://github.com/{{owner}}/{{repo_name}}/security/advisories/new).
2. **Email:** {{contact_email}} (PGP welcome but not required).

Please do **not** open a public issue or pull request for a security
report. Public disclosure should happen only after a coordinated
patch is available.

## What to include

* A description of the vulnerability and its potential impact.
* Steps to reproduce or a proof-of-concept (if you have one).
* The version / commit you reproduced it on.
* Optional: your suggested fix.

## Response SLA

* **Acknowledgement:** within 3 business days.
* **Triage and severity assessment:** within 7 business days.
* **Patch coordination + public advisory:** agreed with the reporter,
  typically within 90 days of the initial report.

## Scope

This policy applies to vulnerabilities in the code shipped by this
repository. Issues in third-party dependencies should be reported
upstream; we'll happily file the downstream tracking issue once a
fix is available.

## Safe harbour

We will not pursue legal action against researchers who:

* Make a good-faith effort to comply with this policy.
* Avoid privacy violations, destruction of data, and degradation of
  service.
* Give us reasonable time to address the issue before public
  disclosure.

Thank you for helping keep `{{project_name}}` and its users safe.
