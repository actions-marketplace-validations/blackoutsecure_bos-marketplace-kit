# Support

Thanks for using `{{project_name}}`! Here's how to get help.

## Self-service first

* **Documentation:** start with [README.md](README.md) and the
  [docs/](docs/) directory if present.
* **Search the issue tracker** for prior reports:
  https://github.com/{{owner}}/{{repo_name}}/issues
* **Search Discussions:** https://github.com/{{owner}}/{{repo_name}}/discussions

## How to file a good question or bug report

1. Provide the **version** of `{{project_name}}` you're using (commit
   SHA or release tag).
2. Provide the **environment** — runner OS, language version, related
   tool versions.
3. Provide a **minimal reproduction** — a tiny repo, a self-contained
   workflow snippet, or a one-line command.
4. Provide the **expected vs. actual** behaviour.
5. Provide **logs** (redact secrets first).

## Channels

* **Bug reports / feature requests:** [GitHub Issues](https://github.com/{{owner}}/{{repo_name}}/issues).
* **Questions / discussions:** [GitHub Discussions](https://github.com/{{owner}}/{{repo_name}}/discussions).
* **Security reports:** see [SECURITY.md](SECURITY.md) — **do not**
  open public issues for security problems.

## Response expectations

This is an open-source project; maintainers respond on a best-effort
basis. There is no commercial SLA. Sponsorship via [GitHub
Sponsors](https://github.com/sponsors/{{owner}}) helps us prioritise.
